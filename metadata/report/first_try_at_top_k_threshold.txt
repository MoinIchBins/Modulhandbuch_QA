6.4 experiment
    ### Top-k + Threshold Parameter Search
    The combined selector was tuned using only parameter regions already identified on the development set. Values of **k = 1, 2, 3** were tested: `k=1` represents the strongest top-k baseline, `k=2` allows retrieval of all required chunks for the multi-chunk gold questions, and `k=3` provides limited additional headroom.
    For each representation, the threshold search was centered on the optimum found during refined threshold tuning. The interval covers two refined threshold steps on either side of this optimum. This allows for a moderate shift in the optimal threshold caused by the additional top-k restriction without reopening a broad threshold search.

    TOP_K_VALUES = [1, 2, 3]

    THRESHOLD_REGIONS = {
        "e5": (0.86514, 0.86781),
        "tfidf": (0.1162375, 0.1390925),
        "sentence_bert": (0.7024, 0.716675),
    }

    EXPERIMENTS = [
        {
            "representation": representation,
            "method": "top_k_threshold",
            "top_k": top_k,
            "threshold": float(threshold),
        }
        for representation, (lower, upper) in THRESHOLD_REGIONS.items()
        for top_k in TOP_K_VALUES
        for threshold in np.linspace(lower, upper, 9)
    ]

    The initial combined search did not bracket the E5 optimum, as the best k=1 configuration occurred at the lower threshold boundary. 
    Because the pure top-1 baseline also substantially outperformed the tested combined configurations, an additional E5-only search was conducted toward lower thresholds. 
    The lower bound was based on the development-set zero-gold score distribution, while the previous search boundary formed the upper bound.
    Only k=1 needs further refinement because it clearly outperformed k=2 and k=3 across the tested E5 threshold range. 
    The purpose of the additional search is therefore not to re-evaluate k, but only to determine whether a lower threshold can improve the already dominant k=1 configuration.

    EXPERIMENTS = [
        {
            "representation": "e5",
            "method": "top_k_threshold",
            "top_k": 1,
            "threshold": float(threshold),
        }
        for threshold in np.linspace(
            0.8164,
            0.86514,
            15,
        )
    ]
    Why 0.8164? It comes from the earlier E5 score-distribution analysis: approximately the 10th percentile of the maximum scores for zero-gold questions. 
    So this expands downward into a region where the threshold still has some abstention effect, rather than arbitrarily going toward zero.
